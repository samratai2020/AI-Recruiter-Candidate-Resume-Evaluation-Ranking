Code quality issues

  • from google.colab import userdata makes the script dependent on Google Colab even though the API key is passed as a command-line argument.
  • Several variables and imports are unused: userdata, combined_payload, lines, cleaned_lines, resume_json_pdf, and resume_json_doc.
  • The code uses inconsistent indentation and naming such as _get_pdf_rawText; it would benefit from PEP 8 formatting and type hints.
  • .replace("`", "").replace("json", "") is unsafe JSON cleanup and can corrupt legitimate text. Use strict JSON parsing or safely extract a fenced JSON block.
  • except Exception in the OpenAI call hides all failure types and returns None, making diagnosis difficult.
  • Only the first file beginning with JD is used; multiple job descriptions are silently ignored.
  • DOCX extraction reads paragraphs only, not tables, headers, or footers, where resume data is frequently stored.

Performance concerns

  1. Inference runs sequentially for every resume with up to max_new_tokens=1000, which is slow for larger directories.
  2. torch.inference_mode() is not used during Qwen generation.
  3. The full set of extracted resumes is sent in one OpenAI request, which can exceed the context window, increase cost, and increase latency.
  4. PDF text uses repeated string concatenation; collect page text in a list and use "\n".join(...).
  5. Pandas is unnecessary for the small transformation used in report generation and adds an avoidable dependency.
  6. HTML is built through repeated string concatenation; use a list of fragments followed by "".join(...).
